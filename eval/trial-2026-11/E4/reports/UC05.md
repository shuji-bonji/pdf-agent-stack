### 署名後のバイト増加と 7.5.6

官報の `verify_integrity` は、Signature1 の署名範囲のあと 9938 バイトがある、と記録している。増分更新の仕組みを述べる節は、`get_requirements` が返した `7.5.6`、見出し Incremental updates である。先頭要求は `R-7.5.6-1`、`level` `shall`。件数は shall 8、may 2、合計 10。

要約する。この shall は、増分更新のとき変更をファイル末尾へ足し、元の内容は残す、というものである。英語の文は載せていない。官報の 9938 バイトは、その観測がこの shall の話題に当たる、という対応づけである。ファイルがこの shall を満たす、とは書いていない。`evaluate_policy` は呼んでいない。

未署名契約は `incrementalUpdateCount` 0 なので、署名後のバイト増加の例には使っていない。

### DocTimeStamp の定義と DSS

定義の節は `12.8.5`。`get_section` の `title` は Document timestamp (DTS) dictionary。直下の見出しは 12.8.5.1 General、12.8.5.2 Initial document timestamp dictionary、12.8.5.3 Subsequent document timestamp dictionaries。ページ範囲は 605 から 607。

型名 `DocTimeStamp` の検索ヒットは 12.8.1 と 12.8.5.3 の 2 件である。12.8.5.1 に要求 ID は返っていない。12.8.5.1 の段落は `get_section` が返したが、本文は貼らない。要約する。文書タイムスタンプ辞書は、トークンが示す時点での PDF ファイル全体の内容を定める、という位置づけが 12.8.5.1 にある。

DSS との関係は、二つの戻りから取る。

- `search_spec` の最高スコアは 12.8.4.2、見出しは Introduction to the document security store (DSS)。snippet は文書全体に適用するタイムスタンプを 12.8.5 へ参照している。12.8.4.2 の `get_section` は未実施。
- `get_requirements` の `12.8.4.3` は DSS の節。shall 6、may 4、合計 10。先頭 `R-12.8.4.3-1` は `shall`。要約する。DSS は、存在するとき、文書カタログの DSS キーの値である辞書である。
- `R-12.8.5.3-3` は `shall`。要約する。後続の文書タイムスタンプを付ける前に、直前のタイムスタンプ証明経路の証明書が、鍵の危殆化または CA の危殆化を理由に失効していなかったことを示す証明書、CRL、OCSP 応答を、DSS 辞書へ入れる。
- `R-12.8.5.3-4` は `shall`。要約する。そのあと、新しいタイムスタンプトークンを新しい文書タイムスタンプ辞書へ置き、構造全体を保護する。
- `R-12.8.5.3-6` は `shall`。要約する。DocMDP の制限を評価するとき、文書タイムスタンプと DSS の存在は無視する。

`R-12.8.5.3-2` の `level` は `may` である。文の内容は失効理由の立証の必要性を述べている。レベルはツールが `may` と返したので、shall とは書かない。

官報のオブジェクト 65 を `locate_objects` が `DocTimeStamp` と返したことと、節 12.8.5 の型名は、同じ語の対応である。そのオブジェクトが 12.8.5 の要求を満たす、とは書いていない。

## 15. コーパスに無い規格への答え

手順は、ISO 19005 や ETSI EN 319 142 を `query` にしていない。答えは `list_specs` の `coverage` だけから書いた。

`coverage.gaps` に、PDF/A として ISO 19005-1、ISO 19005-2、ISO 19005-3、ISO 19005-4 がある。PAdES として ETSI EN 319 142-1 と ETSI EN 319 142-2 がある。`coverage.note` は、ヒットが無いことは「このコーパスは答えられない」であり、「要求が存在しない」ではない、と書いている。そのように書いた。規格が存在しない、とも、規格にその要求が無い、とも書いていない。

追加の `search_spec` は未実施。理由は、手順 2 の query が `document timestamp` だけであり、gaps にある規格を検索して「無い」と書くことが、見てほしい風合いの失敗例だからである。

`ts32002` の description が PAdES という語を含むことは、第2節にツールの説明として残した。ETSI EN 319 142 を引いた記録ではない。
