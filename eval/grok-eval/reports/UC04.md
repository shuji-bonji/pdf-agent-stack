## 1. 目的と入力

日本語の四半期進捗レポート（ダミー）をスクリーンリーダー向けに作り、タグと検証を突き合わせる。不合格側としてタグ無し PDF を同じゲートに通す。機械検証は alt の意味まで見ない。

## 機械検証の範囲

veraPDF が PDF/UA-1 を COMPLIANT と判定（106/106）。T1: ISO 14289-1 の条文は pdf-spec で引ける。今回の合格側に違反は無い。ensure_tagged は宣言であり、この判定の代わりではない。

## 人手レビューが残る範囲

機械検証は alt テキストと読み順が意味的に適切かを判定できない（validate_conformance の notes。ensure_tagged の warning も reading order / alternative text を残すと書く）。H1 が title と本文で二重。図は無いので alt 対象なし。

## 不合格側

ua-untagged: 論理順は捏造していない。veraPDF 非 COMPLIANT。ISO 14289-1 7.1-3（実コンテンツが Artifact でもタグでもない）、7.1-11（StructTreeRoot なし）、6.2-1（MarkInfo/Marked）、7.21.4.1-1（Helvetica 未埋め込み）。pdf-spec 7.1 の shall「All real content shall be tagged」（R-7.1-1）と対応する。

## 4. 想定との差

- 一致した点: タグ付き 106/106。タグ無しは 7.1-3 / 7.1-11 / 6.2-1。extract はタグ無しで空配列 + 理由。条文を pdf-spec で引いた。**0.21.1 の ensure_tagged は CLAIMS warning を返す**
- ずれた点: H1 二重は残る（UC02 と同じ）
- 呼べなかったツール: なし

## 5. 風合い

- 手数: tagged 生成のあと ensure_tagged → reader → validate。感想で済ませていない。宣言のあとに測った
- 責務: なし。不合格を「アクセシブルでない」だけで終わらせず clause を書いた
- 禁止言い回し: なし。「ISO 14289 準拠」とは書いていない
- Report 型: 機械範囲と人手範囲を分けた

## 6. 利用価値

段階: 実務で使える

理由: 合格側と不合格側でゲートが分かれ、条文番号まで落ちる。人が「機械は通ったが alt は見ていない」と判断できる。ensure_tagged の CLAIMS warning が応答に乗るので、測り忘れ防止が ensure_pdfa と揃った。
