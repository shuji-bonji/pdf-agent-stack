## 1. 目的と入力

`long-report.pdf` から支払条件と検収に関する箇所だけ抜く。読めないページは理由を書く。OCR はしない。全文をコンテキストに流し込まない。

Skill 0.2.2 の検体注意に合わせ、キーワード PDF とフィラー PDF を別ファイルで作ってから `merge_pdfs` した。フィラーは見出し 8（キーワード無し）、キーワード側に「支払条件」「再委託の禁止」「検収日」を置いた。21 ページ（指示の 20 以上。50 超にはしていない）。

scan-like はテキスト層がある 1 ページ。画像のみ PDF を writer だけでは作れない（Skill 0.2.2 Phase 4）。指示どおり `render_page` 経路を強制した。`no_text_layer` にはなっていない。

## 4. 想定との差

- 一致した点: summarize を先に呼んだ。21 ページ・`next: []` でも Skill 0.2.2 に従い search_text → 明示 pages の read_text。全文 dump 無し。キーワードは末尾 1 ページに閉じた。render_page は動いた。Read Report の欄を残した
- ずれた点（フィールド名で）: `summarize.next` は依然空（reader の 50 超閾値は変わっていない）。Skill 0.2.2 は空でも箇所抽出なら search_text すると書いてあり、**編成側は一致**。scan-like の `textExtractability` は `no_text_layer` ではなく `extracted`。query=`検収` はフィラーの「語は置かない」に部分一致する
- 呼べなかったツールと理由: なし。pdf-spec の §9.10.1 照会は任意で未実施

## 5. 風合い

- 目的ツールまでの手数: Skill 0.2.2 を読んでから summarize。空の `next` で止めず search_text。単発の全ページ read_text はしていない
- 責務を跨いだ発言（引用、無ければ「なし」）: なし。真正性判定はしていない
- 禁止された言い回し: なし。OCR したとは書いていない。空抽出を「テキストが無い」とはしていない
- エラーからの復帰: フィラー生成で MISSING_GLYPH（本文の誤字）。修正して再試行。FONT_REQUIRED は検体作成で fontPath 済み
- Report の型がサイトと一致したか: pdf-read の Read Report 項目と一致

## 6. 利用価値

段階: 条件付きで使える

理由: 絞り込み経路は 0.2.2 どおり動いた。20 ページ帯でも箇所抽出なら `search_text` に入る。人が「どこを読んだか」を申告から判断できる。残る条件は (1) 画像のみ PDF をこのホストの writer だけでは作れず、スキャン相当の `no_text_layer` 分岐は未測、(2) query の部分一致でフィラーに「検収」が当たる。50 ページ超の `next` 案内と本物のスキャンは別検体が要る。

## 8. 再現手順（最短）

1. キーワード無しフィラーとキーワード 1 ページを別ファイルで `create_markdown_pdf`。`merge_pdfs` で 20 ページ以上
2. `summarize` json。`next` が空でも箇所抽出なら `search_text` → ヒットページだけ `read_text`
3. テキスト層が弱いページは `render_page`（pages 必須）。OCR とは書かない
4. Read Report に読んだ範囲・経路・抽出可能性・読めなかった箇所・切り詰めを残す。欄は消さない
