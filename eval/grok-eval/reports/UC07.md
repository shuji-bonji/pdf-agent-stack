## 1. 目的と入力

`long-report.pdf` から支払条件と検収に関する箇所だけ抜く。読めないページは理由を書く。OCR はしない。全文をコンテキストに流し込まない。

見出し 20 個のダミー報告書。キーワード「支払条件」「再委託の禁止」「検収日」を本文に散らした。2 ページしか出なかったので同一ファイルを 10 結合して 20 ページにした（指示は 20 ページ以上。50 超にはしていない。減らしたのではなく下限を満たした）。

scan-like はテキスト層がある 1 ページ。画像のみ PDF を writer だけで作れなかったため、指示どおり `render_page` 経路を強制した。`no_text_layer` にはなっていない。

## 4. 想定との差

- 一致した点: summarize を先に呼んだ。20 ページで search_text → 明示 pages の read_text。全文 dump 無し。render_page は PDFium で動いた。Read Report の欄（読んだ範囲 / 経路 / 抽出可能性 / 読めなかった箇所 / 切り詰め）を残した
- ずれた点（フィールド名で）: `summarize.next` が空。Skill は pageCount>50 で search_text を next に出す。20 ページでは next が案内しない。UC07 指示は 20 ページ超でも search_text と書いてあるので、Skill の閾値と指示がずれる。scan-like の `textExtractability` は `no_text_layer` ではなく `extracted`
- 呼べなかったツールと理由: なし。pdf-spec の §9.10.1 照会は任意で未実施

## 5. 風合い

- 目的ツールまでの手数: Skill を読んでから summarize。単発の全ページ read_text はしていない
- 責務を跨いだ発言（引用、無ければ「なし」）: なし。真正性判定はしていない
- 禁止された言い回し: なし。OCR したとは書いていない。空抽出を「テキストが無い」とはしていない
- エラーからの復帰: なし（FONT_REQUIRED は検体作成で fontPath 済み）
- Report の型がサイトと一致したか: pdf-read の Read Report 項目と一致

## 6. 利用価値

段階: 条件付きで使える

理由: 絞り込み経路と render_page は動いた。人が「どこを読んだか」を申告から判断できる。ただし (1) 20 ページでは `next` が search_text を案内しない、(2) 画像のみ PDF をこのホストの writer だけでは作れず、スキャン相当の `no_text_layer` 分岐は未測、(3) 結合繰り返しでヒットが全奇数/偶数に広がった。50 ページ超と本物のスキャンは別検体が要る。

## 8. 再現手順（最短）

1. 見出し 20 の markdown を `create_markdown_pdf`。ページが足りなければ `merge_pdfs`
2. `summarize` json → `search_text` → `read_text` にヒットページだけ渡す
3. テキスト層が弱いページは `render_page`（pages 必須）。OCR とは書かない
4. Read Report に読んだ範囲・経路・抽出可能性・読めなかった箇所・切り詰めを残す。欄は消さない
