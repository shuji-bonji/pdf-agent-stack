## 5. 風合い

- 目的ツールまでの手数: Skill を読んでから create → attach → ensure_pdfa → reader → validate。ensure_pdfa のあとに verify を忘れていない
- 責務を跨いだ発言: なし。writer 成功を適合とは書いていない。warning を「もう検証済み」とは読んでいない
- 禁止された言い回し: なし。「ISO 19005 準拠」は使っていない
- エラーからの復帰: 本 UC では FONT_REQUIRED を出さず fontPath 先行。SETUP で next_actions に従う復帰は 1 手で確認済み
- Report の型: Publish Report の操作列・読み戻し・宣言と採点・warnings・ループ回数あり

## 6. 利用価値

段階: 実務で使える

理由: 日本語請求書で write → 読み戻し → veraPDF まで指示どおり回り、人が納品可否を判断できる。PDF/A は T2（veraPDF が COMPLIANT）、PDF/UA-1 は 106/106。Grok 上で veraPDF が PATH から使えた（PDF_VERIFY_VERAPDF 未設定でも engine=verapdf）。fontPath は呼び出し引数が必要（プロセス env に PDF_WRITER_FONT が無い）が、Skill の分岐で足りる。
