# UC10 — 暗号化 PDF と未実施の記録

- 実施日時: 2026-09-15 23:32 JST
- ホスト: Grok Build 1.0.30 (04b7ffed98c6) [stable]
- パッケージ実測版:
  - pdf-reader-mcp: 0.15.1
  - pdf-verify-mcp: 0.26.0
  - pdf-writer-mcp: 0.21.0
  - pdf-spec-mcp: 0.6.0（未使用）
  - veraPDF: 1.30.0（官報では結果なし）
- Skill 使用: あり（pdf-trust / pdf-read の「未実施を passed にしない」）
- 検体パス: `fixtures/incoming/gazette-or-gov.pdf`（公開官報。作業場外へ出さない）

## 1. 目的と入力

暗号化・採点不能を passed にしない。官報は空ユーザーパスワードでオブジェクトは読めるが、PDF/A は測れないことがある。

## 2. 実行ログ

| ステップ | 入力 | 想定 | 実際 |
| --- | --- | --- | --- |
| 1 | `summarize` json | isEncrypted。null と 0 を混ぜない | isEncrypted=true。scope 4 項目 read。textExtractability=**not_extractable**（Identity-V、ToUnicode なし、§9.10.2）。hasText=true（プレビューは文字化け）。pageCount=1。next: 空パスワードで鍵は導けた。decrypt 不要。読めないページは render_page |
| 2 | `get_metadata` | 暗号化フラグ | isEncrypted=true hasSignatures=true isTagged=false author=null |
| 3 | `evaluate_policy` government（UC01） | facts と未実施を分ける | use_with_caution。署名 valid。PDF/A advisory: could not be completed — not performed |
| 4 | `validate_conformance` flavour=pdfa-3b | 失敗または未実施。compliant true にしない | **失敗** `code: INTERNAL_ERROR` message=`veraPDF report contains no validation result`。compliant は返っていない。**未実施**（passed にしない） |
| 5 | `set_metadata` title 変更 | ENCRYPTED_PDF の想定 | **SIGNED_PDF**（/ByteRange）。next_actions: preserveSignatures / allowBreakingSignatures。復号はしていない。暗号化コードより署名ガードが先に発火 |

ツール JSON の要点:

```json
{
  "summarize": {
    "isEncrypted": true,
    "textExtractability": "not_extractable",
    "hasText": true,
    "unreadablePages": [{"page": 1, "state": "not_extractable", "font": "DFHSMinchoRPro6N-W3-Identity-V"}]
  },
  "validate_conformance_pdfa-3b": {"code": "INTERNAL_ERROR", "message": "veraPDF report contains no validation result"},
  "set_metadata": {"code": "SIGNED_PDF", "retryable": true}
}
```

## 3. 成果物

- 出力 PDF: 無し（編集していない）
- Report:

### このホストで測れたこと

- ページ数 1、署名あり、空パスワードで認証できた（evaluate_policy.scope.authenticated=true）
- Signature1 の暗号学的検証は valid。身元 not_evaluated。失効 unknown
- テキストは not_extractable（CMap）。空抽出を「テキストが無い」とはしない
- writer は署名を壊す書き換えを SIGNED_PDF で止めた

### このホストで測れなかったこと（未実施）

- PDF/A-3b: validate_conformance が veraPDF 結果なしで INTERNAL_ERROR。**未実施**。passed にしない
- 本文の Unicode 抽出: not_extractable。render_page は本 UC では未実施（UC07 で PDFium は動くことを確認済み）
- ENCRYPTED_PDF コード: 本検体では SIGNED_PDF が先。暗号化専用の writer エラーは未観測

## 4. 想定との差

- 一致した点: PDF/A を passed にしていない。一部読めたを問題なしに伸ばしていない
- ずれた点（フィールド名で）: writer は ENCRYPTED_PDF ではなく SIGNED_PDF。reader は鍵なしで止まらず、抽出可能性が not_extractable
- 呼べなかったツール: なし。失敗したのは validate_conformance（結果なし）

## 5. 風合い

- 「一部読めた」を「問題なし」に伸ばしていない
- エラーコード INTERNAL_ERROR / SIGNED_PDF を残した。自然文だけにしていない
- revocation unknown を失効していない、とは書いていない

## 6. 利用価値

段階: 条件付きで使える

理由: 未実施の切り分けはできた。ただし (1) 暗号化官報の PDF/A が veraPDF 内部エラーで、Skill が想定する「未実施」より粗い code になる (2) ENCRYPTED_PDF 経路は署名付き検体では観測できない。失敗経路として人は判断できるが、エラーコードの粒度は改善余地がある。

## 7. 改善提案

| 種別 | 対象 | 観察 | 提案 |
| --- | --- | --- | --- |
| MCP の応答 | pdf-verify validate_conformance | 暗号化官報で INTERNAL_ERROR / veraPDF report contains no validation result | 暗号化で採点不能なら ENCRYPTED_PDF または「未実施」用の code に分け、INTERNAL_ERROR と所見を混ぜない |
| 検体 | UC10 | 官報は署名付きなので SIGNED_PDF が先 | 署名無しの暗号化標本を 1 件足すと ENCRYPTED_PDF が測れる |

## 8. 再現手順（最短）

1. 官報を summarize / get_metadata
2. evaluate_policy government。advisory の PDF/A not performed を転記
3. validate_conformance pdfa-3b。失敗なら未実施
4. writer set_metadata。出た code と next_actions を残す。無理に復号しない
