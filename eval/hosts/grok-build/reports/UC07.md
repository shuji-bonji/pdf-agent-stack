## 1. 目的と入力

`long-report.pdf` から支払条件と検収に関する箇所だけ抜く。読めないページは理由を書く。OCR はしない。全文をコンテキストに流し込まない。

フィラー文面から「検収」の自己言及を外して作り直した。キーワード PDF は別ファイル。`scan-no-text-layer.pdf` は `scripts/make-scan-no-text-layer.py` の committed 標本を使った（`--rebuild` していない）。

## 4. 想定との差

- 一致した点: summarize を先に呼んだ。21 ページ・`next: []` でも search_text → 明示 pages の read_text。全文 dump 無し。キーワードは 21 ページのみ。`scan-no-text-layer` が `no_text_layer`。render_page で視覚読み。OCR していない。空抽出を「テキストが無い」としていない
- ずれた点（フィールド名で）: `summarize.next` は依然空（reader の 50 超閾値）。Skill 0.2.2 は空でも箇所抽出なら search_text すると書いてあり、編成側は一致
- 呼べなかったツールと理由: なし

## 5. 風合い

- 目的ツールまでの手数: Skill を読んでから summarize。空の `next` で止めず search_text。単発の全ページ read_text はしていない。画像ページを「内容は空」と切り捨てていない
- 責務を跨いだ発言: なし
- 禁止された言い回し: なし。OCR したとは書いていない
- エラーからの復帰: なし
- Report の型がサイトと一致したか: pdf-read の Read Report 項目と一致

## 6. 利用価値

段階: 実務で使える

理由: 絞り込み経路と画像経路の両方が測れた。20 ページ帯でも箇所抽出なら `search_text` に入る。`no_text_layer` の空抽出を「テキストが無い」にせず、render_page の視覚読みで条項を取れた。人が「どこを読んだか」を申告から判断できる。50 ページ超の `next` 案内は別検体が要るが、Skill 0.2.2 が空 next を補っている。

## 8. 再現手順（最短）

1. キーワード無しフィラー（「検収」を書かない）とキーワード 1 ページを別ファイルで `create_markdown_pdf`。`merge_pdfs` で 20 ページ以上
2. `summarize` json。`next` が空でも箇所抽出なら `search_text` → ヒットページだけ `read_text`
3. `scan-no-text-layer.pdf` を `summarize`。`no_text_layer` なら `render_page`（pages 必須）。OCR とは書かない。空の `read_text` を「テキストが無い」にしない
4. Read Report に読んだ範囲・経路・抽出可能性・読めなかった箇所・切り詰めを残す。欄は消さない
