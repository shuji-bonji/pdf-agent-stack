# UC09 — 宣言と検証の食い違い

- 実施日時: 2026-09-15 23:30 JST
- ホスト: Grok Build 1.0.30 (04b7ffed98c6) [stable]
- パッケージ実測版:
  - pdf-reader-mcp: 0.15.1（未使用）
  - pdf-verify-mcp: 0.26.0
  - pdf-writer-mcp: 0.21.0
  - pdf-spec-mcp: 0.6.0（ISO 19005 は gaps。条文は引かない）
  - veraPDF: 1.30.0
- Skill 使用: あり（pdf-publish の「宣言と適合は別」）。前半は意図的に validate を呼ばない手順
- 検体パス: `fixtures/generated/claim-only.pdf`（Helvetica ASCII）→ `out/claim-only-labeled.pdf`（ensure_pdfa pdfa-3b のみ。UC03 の no-embed と同一バイト列）

## 1. 目的と入力

ensure_pdfa が書いたラベルを適合と誤読しないこと。前半は identify まで。後半で validate。

## 2. 実行ログ

### 前半（validate を呼ばない）

| ステップ | 入力 | 想定 | 実際 |
| --- | --- | --- | --- |
| 1 | `create_text_pdf` 英語、fontPath 無し | Helvetica | font=Helvetica（UC03 で生成し claim-only にコピー） |
| 2 | `ensure_pdfa` pdfa-3b だけ | warning CLAIMS NOT checked | declarationRisks FONT_NOT_EMBEDDED Helvetica。warning あり |
| 3 | `identify_conformance` json | 宣言が読める。合否ではない | pdfA part=3 conformance=B。notes: identifies declared conformance only |

前半の直後の要約（引用）: **「ファイルは PDF/A-3b を名乗っている。ensure_pdfa は文書レベルの /ID・OutputIntent・XMP pdfaid を足しただけで、適合は見ていない。warning は CLAIMS PDF/A-3b … conformance was NOT checked。」** 「PDF/A になった」「ISO 19005 準拠」とは書いていない。

本評価セッションでは UC03 で同じファイルを既に validate 済みだった。UC09 前半の手順としては identify を先に記録し、validate の数値は後半に置く。

### 後半（ゲート）

| ステップ | 入力 | 想定 | 実際 |
| --- | --- | --- | --- |
| 4 | `validate_conformance` flavour=pdfa-3b engine=auto | COMPLIANT とは限らない | engine=verapdf compliant=false 145/146 failedRules=1 |
| 5 | 違反 | フォント等 | `ISO 19005-3:2012 6.2.11.4.1-1` フォント未埋め込み |

正しい報告文: ファイルは PDF/A-3b を名乗っている。veraPDF の判定は非 COMPLIANT（145/146、6.2.11.4.1-1）。ensure_pdfa の warning は CLAIMS … NOT checked。ラベルと採点は食い違う。

```json
{
  "identify": {"pdfA": {"part": "3", "conformance": "B"}},
  "validate": {"engine": "verapdf", "compliant": false, "passedRules": 145, "failedRules": 1}
}
```

## 3. 成果物

- 出力 PDF: `out/claim-only-labeled.pdf`
- Report: 本ファイル

## 4. 想定との差

- 一致した点: identify は宣言、validate は落ちる。warning を省略していない
- ずれた点: このセッション全体では UC03 が先に validate していた。UC09 単体の「罠を踏む」観察は、前半の要約文が準拠と言わなかったこと
- 呼べなかったツール: なし

## 5. 風合い

- identify と validate を同じ「検証した」に畳んでいない
- warning 英文を報告書に残した
- 前半で「準拠した」とは書いていない

## 6. 利用価値

段階: 実務で使える

理由: ラベル付き非適合ファイルを、宣言と採点の差として報告できた。Skill の中心区別が Grok 上で崩れていない。

## 7. 改善提案

| 種別 | 対象 | 観察 | 提案 |
